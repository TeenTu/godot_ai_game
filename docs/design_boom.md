# 《砰砰小队》设计方案 — 移动端解压闯关射击（Godot 4.5 / 竖屏俯视角）

> 参考 `godotengine/godot-demo-projects` 的 3D 示例 + 官方 `tps-demo`，结合本仓库
> `shared/addons/game_kit` 现有能力，面向**移动端**的"解压 / 轻松 / 操作简单 / 反馈强烈"设计。
> 工程目录建议：`games/boom/`。

---

## 0. 一句话定位

**竖屏单手、自动开火、割草式清关。打什么都"嘭"地爆开，60~90 秒一关，排队时能玩，躺床上也能玩。**

玩家全程只需要做两件事：**往哪走**（左手摇杆）和**什么时候放大招**（右下角一个按钮）。
瞄准、开火、换弹、拾取全部自动化。

---

## 1. 形态选择：为什么是"竖屏俯视角"而不是 FPS / TPS

| 维度 | FPS / TPS | 竖屏俯视角（推荐） |
|---|---|---|
| 单局操作 | 左手移动 + 右手转视角 + 右手开火，双摇杆 + 陀螺仪 | **左手摇杆走位，瞄准开火全自动** |
| 学习成本 | 5~10 分钟才不晕 | 30 秒上手，看一眼就会 |
| 视野管理 | 要管理背后 / 转角，精神紧绷 | 全局一眼看穿，注意力全给"躲"和"爆" |
| 晕动症 | 明显（相机旋转 + FOV 拉伸） | 几乎无（相机只平移、不旋转） |
| 移动端屏幕 | 手指挡住半个屏幕 | 摇杆在左下角，战场在中上部，不遮挡 |
| 性能 | 需要高 FOV + 远处 LOD | 固定俯角，可视范围恒定，LOD 与剔除更好做 |
| 市场验证 | 重度向 | 《向僵尸开炮》《弹壳特攻队》等主流解压产品均为竖屏俯视角 |

**结论：保留 FPS/TPS 的"手感技术"，丢掉它的"操作负担"。**

具体说，TPS demo 里的这几样东西我们原样搬到俯视角上：

- `player/camera_noise_shake_effect.gd` — 噪声（FastNoiseLite）驱动的相机震动，比随机抖动更"有质感"
- `player/bullet/` — 子弹 / 曳光 / 弹孔（Decal）分离的场景结构
- 命中反馈四件套：顿帧、震屏、击退、粒子

而 FPS/TPS 的"转视角"这件事，在解压品类里是**负资产**——它把玩家的注意力从
"看爆炸"转移到"看视野"，正好和我们的目标相反。

## 2. 核心玩法与通关目标

### 2.1 关卡循环

```
主界面 ──选关──> 房间战斗（60~90s）──全清──> 三选一升级 ──> 下一房间
                        │                                    │
                        └─ 倒下 → 3 秒原地半血复活（不结束）  └─ 每 5 关：BOSS 房
                                                              └─ 每 30 关：一章结算
```

一关 = 一个封闭竞技场房间（20×20 ~ 40×40 米），2~4 波敌人，全清后出口开门。

### 2.2 通关目标（三层，从松到紧）

| 层级 | 目标 | 说明 |
|---|---|---|
| 基础 | **清空所有波次** | 唯一硬目标，做不到才算输 |
| 弹性 | **三星评价**：通关 / 限时内 / 零受伤 | 星级解锁武器涂装与角色皮肤，不做数值墙 |
| 隐藏 | **破坏值 100%**：打碎房间里所有可破坏物 | 无目的性解压行为，给收集癖留钩子 |

### 2.3 "解压"是怎么设计出来的（关键）

这是一款**没有失败惩罚**的游戏：

- **倒下不是 Game Over**：3 秒后原地半血复活，波次进度保留。只有"打不过"没有"被惩罚"。
- **没有体力 / 没有门票 / 没有强制广告**：随时拿起、随时放下。
- **数值溢出**：从第三关开始，玩家 DPS 永远略高于敌人总血量增长速度。
  难度感来自**数量与视觉压迫**，不来自"打不动"。
- **给无意义行为发奖励**：打碎一个木箱 +1 金币、把敌人炸进泳池 +10 金币。
  纯发泄行为也有正反馈。
- **敌人质感 = 软体**：果冻 / 气球 / 纸箱 / 泡泡。被打中先挤压变形再爆开，
  飞出去撞墙还会弹回来两下。视觉上"无害"，心理上就不紧张。

## 3. 玩家控制与射击手感

### 3.1 操作方案（单手可玩）

```
┌─────────────────┐
│   波次 2/3   ★   │  ← 顶部 HUD（GameKitSafeArea 包裹）
│                 │
│                 │
│      [战场]      │  ← 玩家常驻屏幕下 1/3
│                 │
│  ◯              │  ← 左下：虚拟摇杆（DYNAMIC 模式，拇指区）
│         ╭───╮   │
│         │大招│   │  ← 右下：1~2 个大按钮，带 CD 圆环
│         ╰───╯   │
└─────────────────┘
```

- **左下摇杆**：`GameKitVirtualJoystick`，`mode = DYNAMIC` + `use_input_actions = true`。
  手指落在左下任意位置都能出摇杆（不用精确点固定底座），这是 `3d/platformer` 里
  VirtualJoystick 插件验证过的做法，本仓库 `game_kit` 已内置。
- **右下大招键**：`GameKitTouchButton`，程序化绘制、零素材，直径 ≥ 88px（拇指最小可靠点击区）。
- **没有第二摇杆**：瞄准和开火全自动。

### 3.2 自动瞄准与自动开火

| 机制 | 规则 |
|---|---|
| 目标选择 | 视野内 **加权最近**：距离权重 1.0 + 角度权重 0.6 + 威胁权重（正在冲锋的敌人 ×1.5） |
| 目标吸附 | 准心方向 ±8° 内有敌人时自动吸附；锁定后 0.15s 内不换目标（防抖） |
| 开火 | 有目标即开火，无目标时朝移动方向扫射（打箱子也掉金币，不浪费） |
| 换弹 | 无换弹。改"过热"：连续射击 3s 过热 1s，正好形成"扫—停—扫"的呼吸感 |

**为什么不给手动瞄准？** 手动瞄准 = 需要精读屏幕 = 紧张。
自动瞄准把玩家的注意力从"打中"释放到"躲开"和"看爆炸"，这才是解压。

### 3.3 射击手感四件套（核心资产）

这是整个项目最值得花时间的部分，直接照抄 TPS demo 的技术路线：

| 反馈 | 实现 | 参数 |
|---|---|---|
| **顿帧 hitstop** | 击杀瞬间 `Engine.time_scale = 0.05`，60~80ms 后缓回 1.0 | 普通命中不用，只有击杀/爆炸才触发 |
| **震屏** | `Camera3D` + FastNoiseLite 噪声偏移（TPS demo 同款），按威力分级 | 击杀 0.04、爆炸 0.12、BOSS 破防 0.25（单位：米） |
| **击退 + 挤压** | 敌人受击沿弹道反方向 `velocity` + `scale` 的 squash&stretch（Tween，`EASE_OUT_BACK` 过冲回弹，0.12s） | 击退距离 0.3~1.2m，跟武器走 |
| **命中特效** | `GPUParticles3D` 火花 + `Decal` 地面焦痕（参考 `3d/decals`）+ 飘字 | 飘字走对象池，同屏上限 24 个 |

**防晕三条铁律**（解压品类最容易翻车的地方）：

1. 单次震动幅度硬上限，且**连杀时单次震动衰减 40%**（越爽越不能晃）
2. 顿帧单次 ≤ 80ms，且 0.5s 内最多触发一次（连杀时只吃第一发）
3. 爆炸白闪透明度 ≤ 0.15，持续 ≤ 50ms

### 3.4 移动手感

- 加速 0.12s / 减速 0.10s（有惯性但不飘），转向用 `slerp` 平滑
- 相机跟随带**死区**（玩家在屏幕下 1/3 中心 ±1.5m 内相机不动）+ **前瞻**（沿移动方向偏移 2m）
- 开启 **Physics Interpolation**（`3d/physics_interpolation` demo）：
  即使设备只有 30fps，画面依然顺滑。这对低端安卓机是白送的体验提升。

## 4. 敌人类型与 AI 行为

### 4.1 设计原则

> 敌人存在的意义是**被爽快地打爆**，不是给玩家制造挫败。

因此所有敌人都有明确的**前摇（telegraph）**：攻击前 0.4~0.8s 在地面画红色预警圈
（`Decal`，复用 `3d/decals` 的思路），玩家看懂了就能躲，躲开了就很爽。

### 4.2 敌人表

| 代号 | 形象 | 行为 | 教学目的 | 出现关卡 |
|---|---|---|---|---|
| 果冻兵 | 绿果冻 | 直线冲锋，撞人掉血；移动带 sin 上下浮动 | 走位 | 1+ |
| 水枪兵 | 蓝气球 | 保持 6~8m，停—射—走，弹速慢（8 m/s） | 找掩体 | 4+ |
| 纸箱兵 | 棕纸箱 | 正面免伤，需绕后 / 爆炸破防 | 绕后 | 9+ |
| 炸弹兵 | 红气球 | 贴近后 1.2s 引信，AOE 爆炸（可坑到同伴） | 风筝 | 12+ |
| 分裂兵 | 大果冻 | 死亡分裂 2 只小果冻（小果冻不再分裂） | 连锁爆的爽点 | 16+ |
| 磁铁兵 | 紫泡泡 | 把玩家往自己身上拽（拉扯感，但可挣脱） | 距离管理 | 20+ |
| 精英 | 冰箱怪 | 三阶段：召唤 → 冲撞 → 弹幕；破防后倒地 3s 伤害 ×2 | 节奏起伏 | 每 5 关 |
| BOSS | 大型家电 | 四阶段 + 场地机关（传送带 / 地刺） | 一章高潮 | 每 30 关 |

### 4.3 AI 实现

**寻路**：`NavigationRegion3D` 烘焙 + `NavigationAgent3D`（`3d/navigation` demo 的做法）。
俯视角房间是静态封闭场景，导航网格一次烘焙即可，比手写避障稳得多，且天然支持绕障碍物。

**行为**：`GameKitFsm` 层级状态机（Idle → Chase → Telegraph → Attack → Reposition → Dead），
不用行为树——这个体量用状态机足够，且本仓库 `game_kit` 已内置。

**两个关键细节**：

1. **群体分离（boid separation）**：敌人之间加 0.8m 的分离力，避免叠成一坨。
   这样"一发火箭炸开一群"才有视觉冲击力（`3d/navigation` 的 polyline 跟随代码可直接复用为转向逻辑）。
2. **随机偏转**：参考 `squash_the_creeps` 的 `Mob.initialize()`——
   出生时朝玩家方向 `rotate_y(randf_range(-PI/4, PI/4))`，不走直线。
   这个"歪一点"让敌人看起来笨拙、好笑，而不是机械而危险，是解压感的重要来源。

**生成**：`PathFollow3D` 沿房间边缘 Path 随机取点生成（直接复用 `squash_the_creeps` 的
`SpawnPath/SpawnLocation` + `progress_ratio = randf()` 结构），
但加**分帧生成**——每帧最多生成 3 只（`3d/voxel` demo 的 chunk 分帧思路），避免波次开始时的掉帧尖峰。

## 5. 关卡设计与难度曲线

### 5.1 房间模板化

一关 = 一个 `room_XX.tscn`，由四层拼装：

```
Room.tscn
├── Floor / Walls        # CSG 或 GridMap 快速搭体块（参考 3d/csg）
├── NavRegion            # NavigationRegion3D，一次烘焙
├── Props                # 可破坏物：木箱 / 油桶 / 家具（RigidBody3D，爆碎）
├── Hazards              # 机关：地刺 / 传送带 / 弹板（按需）
└── SpawnPath            # Path3D，敌人沿房间边缘生成
```

关卡**数据驱动**：`scripts/data/levels.gd` 定义 `LevelData : Resource`，
每关一个 `levels/level_XX.tres`（波次表、敌人组合、地形种子、奖励倍率）。
改数值不需要改代码，也不需要开编辑器改场景。

### 5.2 难度曲线：波浪式，不单调上升

单调上升的难度曲线在休闲品类是**错**的——玩家会在第 20 关左右流失。
正确做法是"**紧 — 松 — 紧 — 松**"的情绪节奏：

| 关卡段 | 内容 | 情绪 |
|---|---|---|
| 1–3 | 只有果冻兵，5~8 只；教学提示 | 学会走位 |
| 4–8 | + 水枪兵 + 掩体 | 轻微压力 |
| 9–15 | + 纸箱兵 + 炸弹兵 + 机关 | 需要动脑 |
| **16–20** | **爽关段**：敌人 50+ 只、血量 ×0.5、掉落 ×2 | **纯发泄** |
| 21–28 | + 分裂兵 + 磁铁兵 + 精英 | 再次收紧 |
| **29–30** | **BOSS + 结算** | 一章高潮 |
| 31+ | 循环，敌人换皮 + 数值 ×1.3 | — |

**每 5 关插入一个"爽关"**：敌人血量减半、数量翻倍、掉落翻倍。
这是留存的关键——玩家为了"爽"而多打两关，而不是为了"通关"。

**单关时长 60~90 秒**（移动端碎片时间）。超过 2 分钟就切波次动画。

### 5.3 三星与长线

- 三星：① 通关 ② 限时内（如 70s）③ 零受伤
- 星级解锁：武器涂装、角色皮肤、击杀特效颜色（纯外观，不做数值墙）
- 章节结算：每 30 关一个大结算，掉落稀有皮肤

## 6. 武器与道具系统

### 6.1 武器（关卡内临时生效，Roguelite 轻量化）

| 武器 | 手感 | 解锁 |
|---|---|---|
| 泡泡枪 | 高射速、低伤、连发，入门 | 初始 |
| 霰弹 | 扇形 5 发、击退强 | 第 4 关 |
| 火箭筒 | AOE + 连锁爆炸 | 第 10 关 |
| 链电 | 跳跃 3 个目标 | 第 16 关 |
| 飞盘 | 穿透 + 回旋 | 第 22 关 |
| **黑洞枪** | 吸怪聚成一团再爆 | 第 28 关（最解压） |

**武器在关卡内通过"三选一升级"获得与强化**，不进主界面商店（减少决策负担）：

```
关卡结算 → 三选一（伤害 / 射速 / 弹数 / 穿透 / 暴击 / 拾取范围）
```

选项从 `UpgradePool` 按当前 build 动态抽取——已有穿透就提高"弹数"权重，
保证每一局都能凑出一套**明显超模**的构筑。这是割草类爽感的核心。

### 6.2 道具（场上拾取，即时生效）

| 道具 | 效果 | 时长 |
|---|---|---|
| 加速靴 | 移速 +40% | 8s |
| 磁铁 | 自动吸取全屏金币 | 10s |
| 护盾 | 抵挡一次伤害 | 直到消耗 |
| 狂暴 | 射速 ×2，不过热 | 5s |
| 缓速 | 全场敌人 0.4 倍速 | 4s |
| 金币雨 | 场上刷 30 枚金币 | 即时 |

### 6.3 经济（长线留存）

- 金币 → **大厅永久升级**（攻击 +5% / 移速 +2% / 拾取范围 +10%，递增价格）
- 永久升级是"保底进度"：即使打不过某关，刷两关也能变强 → 消除卡关挫败
- 无强制广告；可选"看广告双倍金币"

## 7. UI 与游戏反馈

### 7.1 HUD（极简，全部走 `GameKitSafeArea`）

```
顶部：血条（左） · 波次 2/3（中） · 金币数（右）
左下：虚拟摇杆
右下：大招按钮（CD 圆环）
中央：Combo 计数（连杀时放大抖动）
```

血条用**分段块**而不是连续条（每格 = 1 点血），受击时对应格碎裂——
比连续条更有"打击感"，也更容易一眼读出还剩几下。

### 7.2 反馈层（"反馈强烈"的具体落地）

| 反馈 | 实现 |
|---|---|
| **飘字** | 普通白 / 暴击金 / 连击放大 1.3×。走对象池，同屏上限 24 |
| **Combo 音效** | 每 5 连击，音高 +1 半音（半音阶递进，越连越亢奋）。用 `GameKitSfx` 程序化合成，**零音频素材** |
| **击杀播报** | DOUBLE / TRIPLE / RAMPAGE，大字 + 过冲抖动（0.3s） |
| **屏幕边缘** | 低血量泛红脉冲；击杀瞬间整屏泛白 5%（≤50ms） |
| **结算** | 最后一击 0.3 倍速慢镜头 → 星级依次弹出 → 金币飞向计数器（数字滚动） |
| **目标指示** | 见下 |

### 7.3 目标指示（移动端小屏的关键）

参考 `3d/waypoints` demo：用 `Camera3D.unproject_position()` 把 3D 坐标投影到屏幕，
直接画 Control 标记（**不用 Viewport / Sprite3D**，性能更好、文字更清晰）。
敌人超出视野时，标记**吸附到屏幕边缘**并变成箭头 + 距离数字。

这在竖屏小屏上是刚需——玩家永远知道"下一波从哪来""道具掉在哪""出口在哪"。

```
│   └── fx/         explosion.tscn  debris.tscn  hit_spark.tscn  shockwave.tscn
├── assets/
│   ├── ART_REQUEST.md         # 素材规格清单（交给 ImageGen / Codex 并行生成）
│   ├── models/  textures/     # 程序化优先，AI 生成补充
│   └── fonts/ui_subset.ttf    # 复用 suika 的中文字体子集（20 KB）
└── tools/play_test.gd         # 无头自检（CI 门禁）
```

### 8.2 四条组织原则

1. **数值即资源**：敌人 / 武器 / 关卡 / 升级项全部是 `.tres` Resource。
   策划改数值不用碰代码，也不用开编辑器改场景。参考 `3d/navigation` 把导航网格
   存成 `navmesh.res` 的做法。
2. **逻辑与表现分离**：`scripts/core/` 不依赖任何 UI 节点，可直接无头断言。
   `scripts/ui/` 只订阅信号。`main.gd` 负责接线。
3. **一切池化**：子弹、敌人、碎片、飘字、Decal 全部走 `object_pool.gd`。
   移动端 `instantiate()` 卡顿是头号杀手，尤其是爆炸瞬间一次生成几十个碎片。
4. **场景小而扁**：一个 `.tscn` 只描述一个实体，不做深层嵌套。
   `player.tscn` 结构参考 TPS demo 的 `player/` 目录拆分方式
   （`model/` `bullet/` `audio/` `textures/` 分目录）。

### 8.3 性能预算（目标：中端安卓 60fps）

| 项 | 策略 | 参考 demo |
|---|---|---|
| 同屏敌人 ≤ 40 | 超出则延迟生成（队列） | `3d/truck_town` |
| LOD | `VisibilityRange` 自动 LOD + 远处敌人换 billboard | `3d/occlusion_culling_mesh_lod`、`3d/visibility_ranges` |
| 阴影 | 只保留一盏 DirectionalLight 投影，禁用点光阴影 | `3d/lights_and_shadows` |
| 波次生成 | 分帧，每帧 ≤ 3 只 | `3d/voxel` 的 chunk 分帧 |
| 渲染器 | **GL Compatibility**（Web 与低端机都能跑） | 本仓库 SOP |
| 物理 | 敌人用 `CharacterBody3D + move_and_slide()`；碎片用 `RigidBody3D` 且 2s 后回收 | `3d/kinematic_character` |
| 平滑 | 开启 Physics Interpolation | `3d/physics_interpolation` |

### 8.4 素材策略

- **优先程序化**：几何体 + 顶点色 + `SurfaceTool` 就能做出果冻/气球/纸箱的卡通感，
  零素材、零加载、零体积（`3d/voxel` demo 就是纯 `SurfaceTool` 建网格）。
- **AI 生成补充**：角色贴图、场景背景图、UI 图标走 `shared/assets` 的
  `flat-cartoon` 风格契约（`docs/asset_pipeline.md`）。
- **特效不走 AI**：爆炸/火花/冲击波用粒子 + 程序化材质，AI 生成的帧序列不稳且体积大。

### 8.5 无头自检（`tools/play_test.gd`，CI 门禁）

照 `dodge` 的标准，至少覆盖 6 项断言，全过才允许部署：

1. 敌人生成数量与波次表一致
2. 伤害计算正确（含暴击、破防 ×2）
3. Combo 计数与播报阈值正确
4. 道具拾取生效与到期回收
5. 波次推进 → 关卡切换 → 出口开启
6. 复活流程（倒下 → 3s → 半血复活，进度保留）
